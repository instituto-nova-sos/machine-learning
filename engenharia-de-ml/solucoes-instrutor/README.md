# Soluções do instrutor

Nível 1: scalers são aprendidos no treino, pesos também; validação, transformação
com estatísticas fixas, regras e escrita de logs são software determinístico.
Nível 2: ver testes de persistência/CLI/provedor. Ordem inválida é erro, não adaptação
silenciosa. Falha explícita deve ter fallback humano, não resposta normal.
Nível 3: exigir versão, dados, testes, processo de aprovação e rollback verificável.
A mesma faixa pode ter prevalência/relações diferentes. Revisão precisa responsável,
contexto e possibilidade de contestação, não apenas um botão que aprova tudo.
